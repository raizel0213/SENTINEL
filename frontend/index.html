      Server scan · local API

      One passive GET request performed by the local backend. Sees all response headers, cookies and basic TLS metadata — not limited by CORS. Recommended for authorized targets.

      Demo profiles

      Simulated records for interface testing and training: mixed findings, a hardened profile, and a weak configuration. No request is ever made for demo profiles.

      Live browser request

      A real fetch() issued by this page. Subject to CORS: servers that do not allow browser access cannot be inspected, and SENTINEL reports that honestly instead of inventing results.

      Responsible use

      Only assess targets you own or have explicit permission to test. Real scans require the authorization confirmation in the UI, and the backend independently rejects requests without it. The SSRF guard blocks private/loopback addresses by default; enable SENTINEL_ALLOW_PRIVATE=1 for your own lab.

        Workspace / 06

        Methodology & limitations

        Understand what this tool can conclude, what it cannot see, and how the score is calculated.

        HTTP security headers

        Checks for HSTS, Content-Security-Policy, X-Content-Type-Options, X-Frame-Options / frame-ancestors, Referrer-Policy, Permissions-Policy, COOP and further hardening signals. Server scans read the full response header set; browser scans only see what CORS exposes.

        Browser boundary

        Cross-origin requests are controlled by CORS. If a server does not allow browser access, browser mode cannot inspect its response headers. It does not bypass CORS. Server mode performs its request from the local backend instead.

        Score model

        Starts at 100 and deducts 15 for a high finding, 8 for medium, 3 for low, and 0 for informational/pass records (25 for critical). The score is clamped to 0–100 and mapped to an educational letter grade. This is a learning aid, not an industry rating.

        Scope

        This is a passive, limited configuration check. It does not crawl, exploit, brute-force, scan ports, or prove whether a site is vulnerable. Missing headers are not automatically exploitable flaws.

        Cookie visibility

        Browsers restrict JavaScript access to Set-Cookie and HttpOnly cookies, so browser mode cannot review cookie attributes. Server mode reads Set-Cookie attributes (Secure, HttpOnly, SameSite) but never records cookie values.

        SSRF guard & safe transport

        The backend refuses private, loopback, link-local and reserved addresses by default. Redirects are never followed blindly: every hop is resolved and re-checked against the destination policy before any connection is made, and sockets connect only to validated addresses (pinning), which also closes the DNS-rebinding window. Redirect loops and chains beyond the configured cap are aborted. Only assess targets you own or have explicit permission to test.
